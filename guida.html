Overrevving è una piattaforma web specializzata nel tracciamento in tempo reale delle classifiche mondiali dei principali sport motoristici su due e quattro ruote per la stagione agonistica 2026. Il progetto nasce per offrire agli appassionati una visualizzazione unificata, priva di pubblicità invasive, ultra-veloce e interattiva, capace di affiancare in un'unica interfaccia sia le categorie del Motomondiale (MotoGP, Moto2, Moto3), sia le derivate di serie (WorldSBK), il fuoristrada iridato (MXGP, MX2) e la Formula 1.

L'infrastruttura tecnologica è costruita secondo la filosofia Jamstack Serverless: il sito non necessita di server applicativi proprietari attivi h24 né di database SQL a pagamento. I dati risiedono su un servizio cloud di archiviazione JSON (JSONBin.io) e vengono aggiornati automaticamente nei fine settimana di gara tramite pipeline GitHub Actions scritte in Python, con il supporto di un pannello amministrativo protetto da credenziali (admin.html) in grado di estrarre i dati direttamente dai bollettini PDF ufficiali di gara.

1. Panoramica del Progetto Overrevving [torna all'indice ↑]

1.1 Finalità e caratteristiche salienti

Il portale Overrevving è stato concepito con l'obiettivo di abbattere la frammentazione informativa che caratterizza il motorsport mondiale. Solitamente, un appassionato o addetto ai lavori deve consultare da 4 a 6 siti web diversi (spesso pesanti, carichi di banner promozionali o protetti da paywall) per monitorare i punti di piloti e case costruttrici tra MotoGP, Superbike, Motocross e Formula 1.

Overrevving risolve questo problema aggregando in una singola pagina a griglia 7 campionati di primo livello:

  • MotoGP Classe regina del Motomondiale FIM.
  • Moto2 Categoria intermedia con propulsori Triumph 765cc.
  • Moto3 Categoria cadetta monocilindrica 250cc.
  • WorldSBK Campionato Mondiale Superbike (moto derivate dalla serie).
  • MXGP Campionato del Mondo di Motocross classe regina (450cc).
  • MX2 Campionato del Mondo Motocross under-23 (250cc).
  • Formula 1 Campionato mondiale FIA monoposto.

1.2 Architettura Jamstack e modello economico Zero-Cost

L'intera infrastruttura sfrutta il pattern Jamstack (JavaScript, APIs, Markup pre-renderizzato). Le caratteristiche fondamentali sono:

  • Nessun server fisso da mantenere: Il portale non necessita di macchine virtuali EC2, VPS o container Docker sempre accesi. L'hosting è delegato all'infrastruttura CDN globale di GitHub Pages, garantendo tempi di caricamento (TTFB) inferiori a 50 millisecondi ovunque nel mondo.
  • Costi di esercizio nulli: Sia GitHub Pages, sia JSONBin.io (nel tier free con fino a 10.000 richieste al mese), sia le GitHub Actions (fino a 2.000 minuti di esecuzione gratuita al mese per account) operano interamente a costo zero.
  • Massima sicurezza e resilienza: Essendo costituito da file statici (HTML, CSS, JS), il sito non presenta superfici di attacco tipiche dei CMS tradizionali (come iniezioni SQL, exploit WordPress o vulnerabilità PHP).

2. Architettura dei Dati e Flusso Informativo [torna all'indice ↑]

2.1 Il ruolo centrale di JSONBin.io

Tutte le pagine del portale non si collegano direttamente e simultaneamente a decine di API esterne (cosa che causerebbe problemi di rate limiting, latenza e blocchi CORS sui browser degli utenti). Invece, si interfacciano con un unico bin cloud hosted su JSONBin.io, che funge da database NoSQL centralizzato (Single Source of Truth).

Parametro Valore di Configurazione Note
BIN ID 6a3064e4f5f4af5e29f7958b Identificativo univoco globale del record cloud
Endpoint di Lettura (Pubblica) https://api.jsonbin.io/v3/b/6a3064e4f5f4af5e29f7958b/latest Utilizzato da index.html e category.html
Metodo di Scrittura PUT https://api.jsonbin.io/v3/b/6a3064e4f5f4af5e29f7958b Riservato alle GitHub Actions e ad admin.html
Header di Autenticazione X-Access-Key: <API_KEY> Richiesto per autorizzare la lettura/scrittura dei dati

2.3 Ciclo di vita dell'informazione: Ingestione, Elaborazione e Visualizzazione

Il percorso compiuto dai dati è suddiviso in tre macro-fasi:

  1. Fase di Raccolta (Ingestion): Le sorgenti ufficiali (API Dorna, API Jolpica, scraping mxgpresults o PDF) rilasciano i punteggi al termine delle sessioni di qualifica e delle gare.
  2. Fase di Normalizzazione & Aggiornamento (Storage): I punteggi vengono estratti, i nomi dei piloti ripuliti, e l'oggetto JSON su JSONBin viene aggiornato tramite una chiamata HTTP PUT con il timestamp corrente salvato nella proprietà _updated.
  3. Fase di Presentazione (Delivery): All'apertura della pagina da parte dell'utente, index.html effettua un'unica chiamata HTTP GET asincrona (fetch()) a JSONBin. I dati vengono trasformati in tabelle HTML in meno di 200ms.

3. Fonti dei Dati e Metodologie di Acquisizione [torna all'indice ↑]

3.1 MotoGP, Moto2 e Moto3: REST API Pulselive (Dorna Sports)

La Dorna Sports, detentrice dei diritti commerciali del Motomondiale, si affida all'infrastruttura cloud di Pulselive per alimentare i widget del sito ufficiale motogp.com. Overrevving si interfaccia direttamente con questi endpoint REST pubblici ad altissima affidabilità:

Parametro Identificativo / Valore UUID 2026
Base URL https://api.motogp.pulselive.com/motogp/v1/results/standings
Season UUID 2026 e88b4e43-2209-47aa-8e83-0e0b1cedde6e
MotoGP Category UUID e8c110ad-64aa-4e8e-8a86-f2f152f6a942
Moto2 Category UUID 549640b8-fd9c-4245-acfd-60e4bc38b25c
Moto3 Category UUID 954f7e65-2ef2-4423-b949-4961cc603e45

L'API restituisce un oggetto contenente un array classification. Da ogni elemento vengono estratti:

  • Pilota: c['rider']['full_name']
  • Punteggio: float(c['points'])
  • Costruttore: c['constructor']['name'] (o c['manufacturer']['name'])
  • Team: c['team']['name']

3.2 Formula 1: REST API Jolpica (Ergast API 2026)

Dopo la dismissione dei server storici di Ergast F1 alla fine del 2024, la community open-source del motorsport ha continuato il mantenimento del database tramite l'iniziativa Jolpica F1. L'endpoint interrogato è: 

GET https://api.jolpi.ca/ergast/f1/2026/driverstandings.json

La risposta rispetta lo standard XML/JSON Ergast (sotto il nodo MRData.StandingsTable.StandingsLists[0].DriverStandings). Per ogni pilota vengono uniti givenName e familyName e parsato il valore numerico del campo points.

3.3 Motocross MXGP e MX2: Web Scraping HTML (mxgpresults.com)

Poiché il promoter Infront Moto Racing non fornisce un'API REST pubblica aperta per il Motocross, Overrevving adotta una tecnica di web scraping mirata sul portale di riferimento mxgpresults.com:

  • URL MXGP: https://mxgpresults.com/mxgp/standings
  • URL MX2: https://mxgpresults.com/mx2/standings

Nello script Python (GitHub Actions) viene eseguita una Regular Expression che cattura le celle della tabella HTML senza caricare librerie pesanti come BeautifulSoup o Selenium: 

rows = re.findall(
    r'<tr[^>]*>\s*<td[^>]*>\d+\s*</td>\s*<td[^>]*>#\d+\s*</td>\s*<td[^>]*>(.*?)</td>.*?<td[^>]*>(\d+)\s*</td>\s*</tr>',
    html,
    re.DOTALL
)
Gestione CORS da browser: Quando l'operazione di scraping viene lanciata manualmente dall'amministratore da admin.html, il browser bloccherebbe la richiesta a mxgpresults.com per la politica Same-Origin. Pertanto, admin.html incapsula l'URL tramite il proxy aperto https://corsproxy.io/?url=....

3.4 Superbike (WorldSBK): Parsing ottico-posizionale di PDF ufficiali

La Federazione Internazionale di Motociclismo (FIM) e Dorna WSBK pubblicano i risultati dei round di Superbike sotto forma di documenti PDF ufficiali (distribuiti sul portale worldsbk.com). A differenza dei file di testo, i PDF non contengono strutture tabellari esplicite, bensì singoli glifi o stringhe posizionate su assi cartesiani (X, Y).

Il sistema implementato in admin.html utilizza PDF.js con un algoritmo proprietario di clustering geometrico:

  1. Il file data/SBK.pdf viene caricato in memoria come ArrayBuffer.
  2. Viene estratta la prima pagina e normalizzata l'altezza del viewport: y = pageHeight - it.transform[5].
  3. Tutti i token con scostamento verticale |y1 - y2| <= 6px vengono aggregati nella medesima riga logica.
  4. Le righe vengono analizzate identificando:
    • Posizione numerica (da 1 a 100).
    • Cognome del pilota (scritto in caratteri MAIUSCOLI).
    • Nome del pilota (scritto in caratteri Title Case, ad es. "Nicolo").
    • Punteggio totale nella colonna di destra.

3.5 Statistiche Costruttori e Team Motomondiale: Estrazione PDF a colonne

I report Dorna MGP.pdf, M2.pdf e M3.pdf presentano un layout inverso rispetto a quello piloti: la tabella di Team e Costruttori è impaginata in colonne verticali (i nomi si trovano sulla riga di intestazione, mentre i punteggi totali sono posizionati sulla coordinata orizzontale X corrispondente, alla coordinata Y dell'etichetta "Points").

La funzione parseTeamsAndConstructors(tokens) presente in admin.html:

  • Localizza la pagina del PDF contenente sia il termine "Constructor" sia il termine "Team".
  • Identifica i token di intestazione e memorizza la coordinata x di ciascun nome.
  • Identifica i token numerici nella fascia Y ∈ [Points - 20, Points + 5].
  • Associa a ciascun costruttore/team il punteggio la cui coordinata X ha distanza euclidea dist < 2px.

4. Automazione Backend tramite GitHub Actions [torna all'indice ↑]

4.1 Il workflow automatico (.github/workflows/update-f1-v3.yaml)

Il "cuore pulsante" dell'aggiornamento automatico è rappresentato dal file di workflow GitHub Actions. Ogni volta che si conclude un Gran Premio o una Sprint Race, la pipeline si avvia in ambiente Linux Ubuntu pulito senza richiedere alcun intervento umano.

4.2 Schedulazione Cron nei weekend di gara e Workflow Dispatch manuale

Il workflow è programmato per attivarsi due volte alla settimana:

on:
  schedule:
    - cron: '0 18 * * 6'   # Ogni Sabato alle ore 18:00 UTC (Post Qualifiche / Sprint Race)
    - cron: '0 18 * * 0'   # Ogni Domenica alle ore 18:00 UTC (Post Gare lunghe della Domenica)
  workflow_dispatch: {}     # Pulsante manuale eseguibile su richiesta dall'interfaccia GitHub

4.3 Algoritmo Python di normalizzazione, merge e push HTTP PUT

Lo script Python incorporato nel runner:

  1. Interroga contemporaneamente le API Pulselive (MotoGP, Moto2, Moto3), lo scraping di mxgpresults.com (MXGP, MX2) e l'API Jolpica (Formula 1).
  2. Scarica lo stato attuale del bin da JSONBin.io (GET /latest).
  3. Esegue il merge selettivo: sovrascrive solo i campionati che hanno restituito dati validi, preservando intatti quelli non ancora disputati o aggiornati via PDF (come la SBK).
  4. Calcola l'ora italiana: datetime.now(timezone.utc) + timedelta(hours=2).
  5. Invia il payload completo a JSONBin.io tramite richiesta PUT con codice di stato HTTP 200 OK.

4.4 Gestione delle credenziali e Secrets di repository

Per impedire la manomissione pubblica del bin da parte di terzi, le credenziali di scrittura non sono archiviate in chiaro nel codice sorgente pubblico di GitHub, bensì memorizzate nelle Encrypted Secrets del repository:

  • JSONBIN_API_KEY: La Master Key di JSONBin abilitata alle scritture PUT.
  • JSONBIN_BIN_ID: L'identificativo esadecimale del record.

5. Interfaccia Utente e Dashboard Pubblica (index.html) [torna all'indice ↑]

5.1 Griglia orizzontale a scorrimento (CSS Grid & Dark Theme)

La homepage presenta un tema scuro moderno (sfondo #1e1e22, pannelli #2c2c32, bordi #3a3a42) studiato per ridurre l'affaticamento visivo e valorizzare i colori sociali delle singole competizioni. La griglia è renderizzata mediante CSS Grid a larghezza fissa (275px per colonna), racchiusa in un contenitore .grid-wrapper con scorrimento orizzontale nativo a inerzia per dispositivi mobili e schermi desktop ultra-wide.

5.2 Riorganizzazione colonne con SortableJS (Drag & Drop)

Su schermi desktop (> 700px), l'utente può trascinare le colonne dei campionati nella sequenza desiderata (ad esempio mettendo la Formula 1 o la SBK al primo posto a sinistra). L'evento onEnd di SortableJS cattura l'ordine e lo memorizza nella chiave overrevving_order del LocalStorage. Su smartphone, l'ordinamento rimane fisso per evitare conflitti con il gesto di scroll orizzontale tattile.

5.3 Sidebar di personalizzazione campionati e persistenza in LocalStorage

Premendo l'icona hamburger in alto a destra si apre una sidebar laterale che consente di:

  • Attivare o disattivare selettivamente qualsiasi categoria tramite checkbox animate.
  • Usare le funzioni rapide "Mostra tutti" o "Nascondi tutti".
  • Ripristinare l'ordine predefinito delle colonne tramite il pulsante dedicato.
  • Le preferenze vengono conservate in memoria locale permanente: overrevving_champs.

5.4 Sistema di Piloti Preferiti (evidenziazione visiva e stella)

Accanto a ogni pilota della tabella è presente un pulsante con una stella (★). Facendo clic:

  • Il pilota viene contrassegnato con la chiave univoca campionato:nome_pilota (es. motogp:Francesco Bagnaia).
  • La riga della tabella assume una colorazione viola evidenziata (#2a1f3a).
  • I preferiti vengono salvati in overrevving_favorites e rimangono attivi alle successive visite al sito.

5.5 Motore di countdown dinamico per i Gran Premi della stagione 2026

Nell'intestazione di ciascuna colonna è presente un timer intelligente. La costante JavaScript CALENDARS_2026 contiene le date ufficiali della domenica di gara per ciascun campionato. La funzione loadCountdown():

  • Trova il primo appuntamento con data futura rispetto all'orologio del dispositivo.
  • Visualizza il nome del circuito e il tempo rimanente in giorni e ore (es. 🏁 → Thailand: 4d 12h).
  • Se la gara si sta svolgendo, mostra 🏁 Round in progress!.
  • A stagione conclusa, mostra 🏁 Season concluded.

5.6 Normalizzazione intelligente dei nomi dei piloti

A causa delle eterogenee convenzioni grafiche tra le varie federazioni (alcune usano COGNOME Nome, altre Nome Cognome tutto maiuscolo), la funzione JavaScript formatName() converte automaticamente ogni pilota nel formato abbreviato standard europeo da classifica televisiva: Iniziale del nome + punto + Cognome (es. M. Marquez, F. Bagnaia, M. Verstappen).

6. Pagine di Dettaglio Categoria (category.html) [torna all'indice ↑]

6.1 Routing lato client basato su URL Query Parameters (?cat=)

Per le categorie che dispongono di dati statistici avanzati (MotoGP, Moto2, Moto3), il titolo di colonna in homepage è un link cliccabile che reindirizza a category.html?cat=motogp. La pagina legge il parametro window.location.search tramite URLSearchParams e adatta dinamicamente:

  • Colore e grafica dell'Hero banner in testata.
  • Dati anagrafici e numero di round previsti.

6.2 Visualizzazione parallela Piloti, Costruttori e Team

La vista di categoria espande la classica graduatoria piloti affiancandovi due pannelli aggiuntivi:

6.3 Calendario completo con calcolo di stato (svolta, in corso, prossima)

La colonna destra di category.html mostra l'elenco cronologico di tutti i Gran Premi dell'anno. Ogni appuntamento viene colorato dinamicamente a seconda della data odierna:

  • Gara conclusa: Opacità ridotta al 55% e segno di spunta grigio.
  • Prossimo Gran Premio: Sfondo evidenziato in viola/blu (#2a2438) con icona di semaforo verde.
  • Gare future: Visualizzazione standard in ordine cronologico.

7. Pannello Amministrativo di Controllo (admin.html) [torna all'indice ↑]

7.1 Controllo accessi e sicurezza con password di protezione

L'accesso alla pagina admin.html è schermato da un overlay di login a tutto schermo (#login-screen). Il codice JavaScript confronta l'input dell'utente con la costante ADMIN_PWD. Solo a password corretta l'overlay viene rimosso dal DOM e vengono caricate le funzioni di sincronizzazione.

7.2 Trigger manuale di aggiornamento live via API del browser

Il pulsante 🔄 Aggiorna MotoGP/Moto2/Moto3/F1 esegue la funzione fetchAllAPI(). Il browser dell'amministratore interroga parallelamente tutte le fonti e mostra una serie di badge di stato in tempo reale:

  • ⏳ Giallo: Chiamata HTTP in corso.
  • ✓ Verde: Dati estratti con successo (con conteggio esatto dei piloti importati).
  • ⚠ Rosso: Segnalazione di errore (timeout, risposta non valida o mancata connessione).

7.3 Parser PDF integrato nel browser (PDF.js)

Tramite i pulsanti verdi 📂 Importa PDF SBK e 📊 Importa PDF Stats, l'amministratore può far leggere a admin.html i file PDF posizionati nella cartella data/ (usando una stringa timestamp per prevenire la memorizzazione nella cache del browser: ?t=Date.now()) oppure trascinare nuovi PDF direttamente dalla propria scrivania. I file vengono elaborati dal motore client-side senza inviare i PDF a server esterni.

7.4 Editor testuale rapido (modifica manuale CSV "Pilota, Punti")

In caso di penalità post-gara, squalifiche dell'ultimo minuto o guasti alle API ufficiali, l'amministratore può premere ✏ Manuale. Si apre un modale contenente una casella di testo con la classifica attuale in formato CSV:

8. Guida Operativa e Manutenzione [torna all'indice ↑]

8.1 Checklist operativa per il fine settimana di gara

Procedura raccomandata:
  1. Venerdì/Sabato mattina: Non è richiesta alcuna azione. Il sito visualizza il countdown al Gran Premio.
  2. Sabato sera (ore 18:00 UTC / 20:00 IT): La GitHub Action si attiva da sola al termine delle Sprint Race / qualifiche ed aggiorna i punti del sabato.
  3. Domenica sera: Al termine dei Gran Premi, la GitHub Action si riattiva e registra le classifiche ufficiali complete.
  4. Per la Superbike (WorldSBK): Quando FIM pubblica il PDF della gara, salvare il documento nella cartella data/SBK.pdf, eseguire un commit su GitHub e premere in admin.html il pulsante "Importa PDF SBK".

8.2 Risoluzione anomalie (Troubleshooting API, CORS, parsing PDF)

Problema riscontrato Causa probabile Soluzione pratica
Il sito mostra "⚠ Error loading standings" Raggiunto il limite di chiamate su JSONBin oppure API Key disabilitata Accedere alla dashboard di JSONBin.io, verificare il credito mensile o generare una nuova Access Key
La colonna F1 o MXGP è vuota L'API Jolpica è temporaneamente offline o mxgpresults.com ha cambiato struttura HTML Aprire admin.html e aggiornare il punteggio tramite l'editor manuale (✏ Manuale)
Il parser SBK dice "0 piloti trovati" Il PDF fornito è un formato scansionato come immagine raster anziché testo vettoriale Assicurarsi di scaricare il PDF originale con testo selezionabile dal sito worldsbk.com

8.3 Rotazione delle chiavi API JSONBin e password amministratore

Se si desidera cambiare la password di admin.html o la chiave segreta di JSONBin:

  • Password Admin: Modificare la variabile const ADMIN_PWD = 'nuova_password'; alla riga 187 di admin.html.
  • Chiavi JSONBin sul frontend: Modificare le costanti BIN_ID e API_KEY all'interno di index.html e admin.html.
  • Chiavi JSONBin sul backend automatico: Andare sulle impostazioni del repository GitHub: Settings > Secrets and variables > Actions e aggiornare i valori di JSONBIN_API_KEY e JSONBIN_BIN_ID.

9. Glossario Tecnico e Riferimenti Esterni [torna all'indice ↑]

Jamstack
Architettura di sviluppo web moderna basata su JavaScript lato client, API riutilizzabili e Markup pre-costruito distribuito su CDN.
CORS (Cross-Origin Resource Sharing)
Meccanismo di sicurezza del browser che impedisce a uno script su un dominio di richiedere risorse su un dominio differente. Nel progetto viene superato tramite backend GitHub Actions (che non ha vincoli browser) o tramite corsproxy.
JSONBin.io
Servizio SaaS di cloud storage per file JSON accessibile tramite semplici chiamate REST (GET, PUT, POST).
PDF.js
Libreria JavaScript creata da Mozilla Labs per renderizzare e parsare documenti Portable Document Format senza plugin esterni.
